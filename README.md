# opic studio

Ava와 연습하는 OPIc 웹앱. Next.js · shadcn/ui · Lucide React 기반이며 현재는 개인 PC에서 실행합니다. 공식 시험 서비스와는 무관합니다.

## 실행

macOS와 Windows에서 실행할 수 있습니다. Node.js **22.18 이상**이 필요합니다([nodejs.org](https://nodejs.org) LTS 설치, macOS는 Homebrew `brew install node`도 가능). `node -v`로 버전을 확인하세요.

**macOS** — 프로젝트 폴더의 터미널(zsh)에서 실행하세요.

```bash
npm ci   # 처음 설치할 때
[ -f .env.local ] || cp .env.example .env.local
npm run dev
```

**Windows** — 프로젝트 폴더의 PowerShell에서 실행하세요.

```powershell
npm ci   # 처음 설치할 때
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)을 엽니다. 이후에는 `npm run dev`만 실행하면 됩니다. 종료는 `Ctrl+C`입니다.

- `.env.example`은 설정 예시, `.env.local`은 실제 설정입니다. Next.js가 `.env.local`을 읽습니다.
- 복사는 설정 파일을 만들기 위한 편의 단계이며 필수는 아닙니다. 위 명령은 기존 파일을 덮어쓰지 않습니다.
- API 키는 직접 입력해야 합니다. 설정을 바꿨다면 앱을 재시작하세요.
- 최적화 실행: `npm run build` 후 `npm start`. 개발 서버와 같은 포트를 동시에 사용하지 마세요.
- 3000번이 사용 중이면 `npm run dev`는 3001번에서 열리며, 이 주소에서도 앱을 그대로 쓸 수 있습니다. 단, ChatGPT 연결(로그인)은 등록된 3000번 주소에서 진행됩니다.
- 브라우저는 최신 Chrome·Edge를 권장합니다. macOS에서 처음 녹음할 때 **시스템 설정 → 개인정보 보호 및 보안 → 마이크**에서 사용하는 브라우저를 허용해야 합니다. 허용 후 브라우저를 다시 시작하세요.
- 질문·교정문 음성은 브라우저가 제공하는 영어 음성 중 가장 자연스러운 것을 고릅니다: Ava 프리미엄/향상 → Edge Natural 음성 → 기타 프리미엄/향상 음성 → Google US English → Samantha 순. macOS에서는 **시스템 설정 → 손쉬운 사용 → 읽기 및 말하기 → 시스템 음성 → 음성 관리**의 영어(미국)에서 **Ava (프리미엄)**을 내려받은 뒤 브라우저를 다시 시작하세요. Chrome이 내려받은 음성을 표시하지 않으면 Google US English가 사용됩니다.

## 사용법

1. **체험 계정**으로 시험·녹음을 둘러보거나, **ChatGPT 연결**로 본인 구독의 AI 평가 권한을 연결합니다.
2. 홈에서 **목표 등급**을 정하고 모의시험 또는 문제 라이브러리의 **한 문항 연습**을 시작합니다.
3. 종료 후 녹음을 듣고 **GPT 전사**를 요청합니다. 인식 오류는 직접 수정할 수 있습니다.
4. **내 구독으로 평가받기**를 누르면 문법·내용 교정과 목표별 근거·보완점·다음 연습을 받습니다. 문법은 별도 요청으로 모든 문장을 점검하므로 평가 1회에 구독 요청이 한 문항 연습은 2번, 12·15문항 모의시험은 4번 발생합니다.
5. 교정문 듣기·단어 클릭·속도 조절로 반복 연습합니다. **교정 예시 보기**는 AI 호출 없이 확인할 수 있습니다.
6. 문법 카드의 **개념 보기**나 **문법 노트**에서 개념 설명, 내가 틀린 문장, 반복 오류를 확인하고 **고쳐 쓰기**로 내 문장을 다시 고쳐 봅니다.

모의시험은 전체 40분, 12/15문항이며 일곱 문항 후 난이도를 다시 선택합니다. 한 문항 연습은 고른 문제 하나만 진행합니다.

목표 변경은 새 연습에 적용하며 예전 기록은 당시 목표를 유지합니다. 질문이 요구하지 않은 능력은 확인 불가로 표시합니다. 목표 코칭은 공식 등급 판정이 아니며 발음·억양·멈춤은 전사문으로 평가하지 않습니다. IM1·IM2·IM3의 세부 연습 초점은 앱에서 구분한 것으로 공식 합격 기준이 아닙니다.

예전 기록에 목표 코칭이 없다면 **목표 피드백 포함해 다시 평가**를 누르세요. 자동 재평가하지 않습니다.

이전 기준으로 문법을 점검한 기록은 문법 노트에 모이지 않습니다. 복습 화면의 **문법 다시 점검**을 누르면 코칭은 그대로 두고 문법만 새로 점검합니다. 이 요청도 본인 구독 사용량을 사용합니다.

## GPT 전사 설정과 비용

`.env.local`에 입력한 뒤 재시작하세요. 아래의 `<...>`는 실제 발급받은 값으로 바꿉니다.

```dotenv
OPENAI_TRANSCRIBE_API_KEY=<전사용 OpenAI API 키>
OPENAI_TRANSCRIBE_MODEL=gpt-transcribe
```

**GPT 전사는 별도 API 비용**, **AI 평가는 본인 ChatGPT 구독 사용량**을 사용합니다. 두 연결은 별개입니다. 키는 사용 권한, 모델 이름은 호출할 모델을 정합니다.

전사는 녹음 전송·비용 안내에 동의하고 버튼을 눌렀을 때만 실행합니다. 직접 수정한 전사와 완료한 GPT 전사는 보존하며 실패한 클립만 재시도합니다. 전사문이 바뀌면 이전 피드백은 초기화됩니다. 키가 없으면 실제 답변을 직접 입력할 수 있습니다.

녹음 중 브라우저 전사는 임시 전사이며 브라우저 공급자의 서버를 사용할 수 있습니다. 질문·교정문 듣기는 브라우저 음성 합성을 사용해 별도 TTS API를 호출하지 않습니다. 원본 녹음의 단어별 시간 이동과 로컬 음성 분석은 제공하지 않습니다.

## 바꿀 수 있는 부분

| 항목 | 변경 방법 |
| --- | --- |
| 전사용 키 | `OPENAI_TRANSCRIBE_API_KEY` 변경 후 재시작. 키 소유자의 API 비용 발생 |
| 전사 모델 | 같은 OpenAI API의 호환 모델은 `OPENAI_TRANSCRIBE_MODEL` 변경 가능. 현재 전송·응답 형식 지원 여부 확인 필요 |
| 다른 전사 서비스 | **현재 코드는 OpenAI 전사 구조만 지원.** 키만 바꾸면 안 되며 개발자·코딩 LLM에게 연동 수정을 요청 |
| 평가 모델 | **계정 및 설정**에서 본인 계정에 허용된 모델 선택. 기본 선호값은 `OPENAI_MODEL`, 추론 강도는 `OPENAI_REASONING_EFFORT=medium` |
| 문법 점검 추론 강도 | `OPENAI_GRAMMAR_REASONING_EFFORT` (비워 두면 `OPENAI_REASONING_EFFORT`). 높이면 더 꼼꼼하지만 느려질 수 있음 |
| 문법 개념 설명 | `src/lib/grammar-concepts.ts`의 개념별 규칙·예문·팁 수정. 개념 ID를 바꾸면 기존 기록의 개념 태그와 맞지 않음 |
| 다른 평가 제공자 | 현재는 ChatGPT 구독 구조. Claude·Gemini 등은 인증·요청·응답·비용 처리의 코드 수정 필요 |
| 목소리 | 현재는 브라우저 영어 음성. 외부 TTS로 교체하려면 별도 구현 필요 |
| 저장 위치 | `DATA_DIR` 변경. 기존 기록은 자동 이동되지 않으므로 먼저 백업 |

다른 전사 API로 바꾸려면 LLM에게 이렇게 요청하세요. 실제 키는 전달하지 마세요.

> 전사를 [서비스·모델]로 교체해 줘. 현재는 OpenAI 구조만 있으므로 `src/server/transcription.ts`와 설정·화면을 새 API에 맞춰 수정해 줘. 전송 동의, 직접 수정한 전사 보존, 완료 클립 재호출 방지, 실패 후 이어하기는 유지하고 비용 안내·README·테스트도 갱신해 줘.

## 로컬 데이터와 배포 전 확인

| 위치 | 공개하면 안 되는 내용 |
| --- | --- |
| `.env.local` | API 키·OAuth secret·AUTH_SECRET 등 설정 |
| `.data/` | 계정·시험·전사·피드백·녹음·암호화한 연결 정보·암호화 키 |
| `output/`, `tmp/`, `.playwright-cli/` | 테스트 DB·캡처·PDF 렌더링·브라우저 상태·로그 |
| `opic_guide.pdf` | 사용자가 제공한 원본 참고 자료. 배포 제외 |

Git·Docker 제외 규칙을 적용했습니다. **전체 폴더를 ZIP으로 묶으면 제외 규칙이 자동 적용되지 않습니다.** 이미 커밋한 비밀값은 제외 규칙으로 지워지지 않으므로 키 폐기·재발급과 이력 정리가 필요합니다.

```bash
npm test
npm run typecheck
npm run build
npm run security:check
```

문법 점검 품질은 `npm run grammar:check -- --yes`로 확인합니다. 직접 작성한 학습자형 답변 3개(오류 16곳)를 실제 모델로 점검해 찾은 오류 비율과 맞는 문장을 오류로 표시했는지 보여 줍니다. 연결된 계정의 구독 사용량으로 요청 1회를 보내며, `--yes` 없이 실행하면 호출하지 않습니다.

보안 점검은 비밀값 노출 패턴·로컬 비밀값의 소스/브라우저 번들 포함·Git 제외 규칙·로컬 데이터 개수를 확인합니다. 값이나 답변은 출력하지 않고 데이터를 삭제하지 않습니다. Git 저장소가 아니면 추적 파일·커밋 이력은 검사할 수 없습니다.

기록 삭제는 **학습 기록**에서 합니다. 앱 종료·로그아웃으로 데이터가 삭제되지는 않습니다. 백업은 서버를 종료한 뒤 `.data/`와 해당 암호화 비밀값을 안전하게 보관하세요.

## 원격 서비스로 배포할 때

개인 로컬 OAuth와 서비스 승인은 별개입니다. 승인된 서비스 클라이언트·HTTPS·운영 전용 비밀값과 비어 있는 별도 저장소가 필요합니다. 로컬 데이터·자격증명을 운영으로 복사하지 마세요.

운영은 `APP_MODE=service`, 실제 HTTPS `APP_URL`, 충분히 무작위인 32자 이상 `AUTH_SECRET`, 승인된 `CHATGPT_CLIENT_ID` 등을 설정하고 `npm run build` → `npm run start:service`로 실행합니다. Docker 예시는 `docker compose up --build -d`이며 실행 시 환경 파일과 영속 볼륨을 사용합니다.

현재는 영속 디스크를 쓰는 단일 Node.js 서버 구조입니다. 실제 서비스 승인·원격 배포·유료 API 호출은 별도 검증이 필요합니다. 자동 테스트와 모의 AI 응답 검증이 실제 평가 정확도를 보장하지는 않습니다.
