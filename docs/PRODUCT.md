# opic studio — 서비스 기획

목표는 첫 응시자의 긴장을 줄이는 반복 가능한 시험 경험이다. 한국 OPIc 공식 안내와 사용자가 제공한 80쪽 가이드를 참고했으며, 공식 시험을 판매하거나 실제 기출을 재배포하지 않는다. 사용자의 최종 지시에 따라 현재 제공 범위는 로컬 전용 실행이며, 서비스용 외부 승인은 추후 배포 단계의 요구사항이다.

## 사용자 흐름

문제 라이브러리와 홈의 ‘한 문항 연습’은 아래 전체 모의시험 준비와 분리한다. 선택한 질문 확인 → 계정 연결(필요할 때) → 녹음·외부 전송 확인 → 마이크 권한 확인 → 선택한 1문항 답변 → 복습·피드백 요청 순서다. 설문·난이도 선택·4단계 장비 점검은 거치지 않는다. 마이크 권한이 거부되면 기록을 만들지 않는다. 새로고침·같은 출처의 계정 연결 복귀·다시 연습하기에서 선택한 문제를 유지한다. 잘못된 문제 ID는 서버에서 거절하며 전체 문제 세트로 바꾸지 않는다.

아래는 실전 모의시험 흐름이다.

1. ChatGPT 계정 로그인 → 계정별 학습 홈. 운영 환경에서는 체험 계정을 발급하지 않는다.
2. 배경 설문: 직업, 학생 여부, 거주 형태, 관심사. 실전 모드는 12개 이상, 자유 연습은 3개 이상 선택한다. 설문 항목은 재구성했으며 실제 최신 항목 전체와 동일하지 않다.
3. 자기평가: 1–6단계, 목표 등급 별도 선택. 기본은 난이도 4, 15문항. 12문항도 준비용으로 직접 선택할 수 있다.
4. 장비 점검: 영어 음성 재생, 실제 마이크 녹음, 녹음 재생 및 확인. 점검 음성은 서버에 전송하지 않는다.
5. 시험 안내와 데이터 처리 확인. 준비 시간은 20분을 표시하되 초과해도 점검을 마칠 수 있다.
6. 본시험: 서버에서 시작 시각과 40분 마감 시각을 확정한다. 문항별 제한이나 일시정지는 없다. 재접속해도 마감 시각을 유지한다.
7. 시험관 Ava의 질문 듣기 최대 두 번 → 답변 녹음 → 제출과 다음 문항. 실전 모드는 자막·힌트·중간 평가·재녹음을 숨긴다. 답변 시작 버튼은 실제 브라우저의 음성 권한·재생 안정성을 위한 학습용 차이다.
8. 7문항 제출 후 쉬운 질문/비슷한 질문/어려운 질문 선택. 남은 문제만 새 난이도로 구성한다. 전체 타이머는 계속 흐른다.
9. 12개 또는 15개 문항 제출, 40분 만료 또는 명시적 종료 → 녹음 복습. 최종 음성 업로드에만 30초 전송 여유를 둔다.
10. 녹음 중 브라우저가 영어를 전사 → 사용자가 본인의 ChatGPT 구독으로 AI 평가 요청 → 전체 전사문 종합 피드백 → 문항 근거·개선 표현·다음 연습 계획. 자동 전사가 없으면 종료 후 실제 발화를 직접 입력할 수 있다.

## 문항 구성

현재 자체 제작 라이브러리는 192개다. 23개 생활·관심 주제 각각 6유형, 돌발 주제 6개 각각 5유형, 롤플레이 8상황 각각 3유형으로 구성한다. 공통 틀에서 주제별 내용을 조합한 초안이며 전문가의 문항 검수와 실제 수험생 파일럿이 필요하다.

- 1번: 자기소개 준비운동. AI 등급 추정에서 제외한다.
- 2–4번: 선택 주제 A의 묘사·일상·경험.
- 5–7번: 선택 주제 B의 묘사·일상·경험.
- 8–10번: 돌발 생활 주제의 연결 질문. 12문항 세트는 8–9번으로 줄인다.
- 11–13번: 정보 질문 → 문제 해결 → 유사 경험. 12문항 세트는 10–12번.
- 14–15번: 높은 초기 난이도에서는 비교·의견, 그 외에는 준비 과정·처음 경험.

이는 앱의 연습 설계다. 특정 유형이 공식 시험의 특정 번호에 나온다고 주장하지 않는다. 공식 출제 알고리즘과 난이도별 분포는 공개 범위만으로 복원할 수 없다. 본 앱의 난이도 조정도 공식 알고리즘을 검증해 재현한 것이 아니다.

## AI 평가

기본 모델은 공식 카탈로그에서 확인한 `gpt-6-luna`, reasoning `medium`이다. 요청의 `6.1 luna`는 현재 확인한 공식 API 카탈로그에서 검증되지 않아 임의 ID로 하드코딩하지 않았다. `OPENAI_MODEL`로 접근 가능한 모델을 변경할 수 있다. 학습 피드백용 시작점으로 적절하다는 설계 판단이며 평가 정확성은 검증되지 않았다.

음성은 브라우저 SpeechRecognition으로 전사한다. 이 서비스는 브라우저 공급자의 서버로 음성을 전송할 수 있으므로 시작 전 고지한다. 실제 녹음은 별도로 저장한다. 브라우저 미지원·실패 시 종료 후 전사를 직접 입력한다. ChatGPT 구독 연동은 현재 전사 API와 음성 입력을 지원하지 않으므로 외부 전사 API에 구독 토큰을 사용하지 않는다. 발음·억양·발화 속도·실제 전달의 유창성은 평가할 수 없음을 명시한다.

선택 기능으로 `gpt-transcribe` 전사를 추가했다. 별도 전사 API 키를 설정하고 사용자가 종료 후 외부 전송과 별도 사용량을 확인한 요청에만 실행한다. 직접 수정한 전사문은 보존하고, 완료한 클립을 체크포인트로 저장한다. 종합 피드백에는 원문에 근거한 문법 최소 수정과 한국어 설명을 담으며 선택적인 자연스러운 표현은 문법 오류와 구분한다.

평가 기능은 수행 기능, 내용·맥락, 표현의 정확성과 이해 가능성, 발화 구성으로 나뉜다. 영역별 1–5는 학습용 지표이며 공식 점수가 아니다. 정답 개수·발화 길이·선택 난이도·목표 등급으로 등급을 계산하지 않는다. 전사문 내부의 지시는 수행하지 않도록 안내하고 출력 스키마와 인용 근거를 서버에서 검증한다.

단일 문항, 미완료 시험, 실질적인 답변 3개 미만, 주제 범위 부족 등은 추정 등급을 내지 않는다. 충분한 표본도 넓은 인접 범위와 낮음/보통 확신도로만 제시한다. IM 세부 등급과 실제 ACTFL 판정을 자동으로 검증할 수 없다. 서비스 출시에 앞서 공인 평가자와 교차 검증해야 한다.

## 목표 등급 피드백

IL·IM1·IM2·IM3·IH·AL별 학습 프로필을 `src/lib/target-profiles.ts`에서 관리한다. 공개된 말하기 수준 설명을 참고해 앱에서 작성한 연습 목표이며 공식 채점표·합격선이 아니다. IM1·IM2·IM3은 IM 설명을 공통 바탕으로 연습 초점을 구분하고 이 한계를 화면에 표시한다.

평가 요청에는 해당 시험에 저장된 목표와 네 가지 기준(과제 수행·답변 구성·시점 표현·의미 전달)을 포함한다. 목표는 코칭에만 반영하고 현재 수준 추정과 공통 영역 점수를 목표에 맞춰 올리지 않는다. 한 번의 평가 요청에서 공통 피드백과 목표 코칭을 함께 받는다.

각 기준에 대해 전사문에서 확인/보완하며 연습/확인 기회·근거 부족 상태, 실제 인용과 문항 번호, 다음 연습을 제공한다. 서버는 잘못된 목표·중복 기준을 거부하고 없는 인용·미응답·자기소개 근거를 제외한다. 판단 근거가 사라진 항목은 확인 불가로 낮춘다. 질문이 요구하지 않은 능력은 실패로 처리하지 않으며 전사로 발음·억양·속도를 판단하지 않는다. 한 문항 연습에도 코칭은 제공하지만 추정 등급은 기존 표본 제한을 유지한다.

홈에서 바꾼 목표는 새 연습에 반영한다. 기존 기록은 당시 목표를 유지한다. 예전 피드백에 목표 코칭이 없을 때는 사용자가 명시적으로 재평가를 요청해야 하며 자동으로 구독 사용량을 소모하지 않는다. 교정 예시에는 작성된 IH 목표 코칭을 추가해 실제 모델 호출 없이 형식을 살펴볼 수 있다.

## 문법 점검과 문법 노트

문법은 코칭 평가와 별도의 요청으로 점검한다. 답변 5개씩 나눠 코칭 요청과 동시에 보내므로 대기 시간은 늘지 않지만, 평가 1회에 구독 요청이 한 문항 연습은 2번, 12·15문항 모의시험은 4번 발생한다. 동시 요청이 토큰 갱신을 두고 충돌하지 않도록 먼저 한 번 갱신한다. 일부 묶음이 실패하면 불완전한 결과를 저장하지 않는다. 시간당 평가 제한과 평가 잠금은 함께 사용한다. 문법 점검은 모든 답변을 문장 단위로 확인해 같은 오류도 나올 때마다 기록하고, 문항 유형으로 기대 시점을 정한다. 예를 들어 과거 경험 문항에서 지난 일을 현재형으로 말하면 시제 오류다. 말을 고르며 반복·수정한 부분, 대화체 시작·마무리 표현, 축약형은 오류로 보지 않으며 발음·속도·유창성은 판단하지 않는다. 문장부호·대소문자·문장 나눔은 전사기가 만든 것이므로 오류로 보지 않고, 서버도 이것만 바꾸는 수정을 버린다. 교정 범위는 카드만 봐도 읽히도록 오류를 포함한 2~5단어로 요청하며, 복습 카드는 해당 문장 전체와 그 문장의 모든 문법 수정을 반영한 문장을 함께 보여 준다. 전사 오류일 수 있는 항목은 빼지 않고 ‘녹음 확인 필요’로 표시한다.

각 수정에는 `src/lib/grammar-concepts.ts`의 문법 개념 ID를 1~3개 붙인다. 개념 설명·예문·팁은 앱에서 작성한 고정 콘텐츠라 모델 호출 없이 보여 준다. 서버는 원문에 없는 인용, 바뀌지 않은 수정, 중복, 미응답 답변을 버리고 읽는 순서로 정렬한다. 문법 점검만 실패하면 코칭은 저장하고, 이 경우와 이전 기준 기록에는 복습 화면에서 문법만 다시 점검하는 버튼을 제공한다. 사용자가 누를 때만 요청한다.

문법 노트는 새 기준으로 점검한 기록만 개념별로 모은다. 여러 답변에서 나오거나 한 답변에서 세 번 이상 나온 개념은 ‘반복 오류’로 표시한다. 오류가 나오지 않았다고 익혔다고 보지 않는다. 마지막 오류 뒤 그 개념을 쓸 기회가 있었던 답변(예: 과거 시제는 과거 경험·비교 문항) 2개 이상에서 다시 나오지 않을 때만 ‘최근 답변에서 안 나옴’으로 표시한다. 표현 제안은 오류 횟수에 넣지 않는다.

고쳐 쓰기 연습은 내가 말한 문장을 보여 주고, 직접 고친 문장을 같은 문장의 모든 문법 수정을 반영한 교정문과 비교한다. 대소문자·문장부호·흔한 축약형 차이는 무시하고, 다른 표현도 맞을 수 있으므로 직접 정답으로 인정하는 버튼을 둔다. 비교는 브라우저에서 하며 AI를 호출하지 않고 결과를 저장하지 않는다.

## 교정문 듣기

복습과 교정 예시 화면에서 교정 문장·선택적 표현·전체 답변을 브라우저 영어 TTS로 들을 수 있다. 0.75× / 0.9× / 1.0×를 제공하고, 속도를 바꾸면 선택한 시작 위치부터 다시 읽는다. 교정문의 단어를 누르면 해당 단어부터 이어 읽으며 같은 단어를 다시 눌러 반복할 수 있다. 방향키와 Enter/Space로도 탐색·재생한다. 드래그로 선택한 텍스트를 복사하는 동작은 재생하지 않는다.

한 번에 한 구절만 재생하고, 다른 구절·내 녹음 재생·문항 변경·화면 이동 시 기존 낭독을 정지한다. 전체 답변은 원문의 위치가 유일하게 확인되는 문법 수정만 반영한다. 겹치거나 반복되어 위치가 불분명한 수정은 개별 교정 카드에서 제공하며, 선택적 표현을 전체 답변에 자동으로 섞지 않는다. 긴 답변은 짧은 발화 단위로 순서대로 재생한다.

이는 합성 음성으로 교정문을 읽는 기능이다. 원본 녹음은 기본 오디오 플레이어에서 듣는다. 원본 녹음의 단어별 시간 정렬·발음·억양·멈춤 자동 분석은 제공하지 않으며 별도 TTS API는 호출하지 않는다.

## 계정·데이터·배포

다중 수험생 서비스다. 모든 기록 및 녹음 경로에서 서버 세션과 소유권을 검사한다. ID를 알아도 다른 사용자의 자료는 볼 수 없다. SQLite 낙관적 리비전으로 동시 제출 덮어쓰기를 차단한다. AI 중복 실행은 데이터베이스 잠금으로 막고 계정별 요청 수를 제한한다. 전사문과 녹음을 함께 제출한다.

ChatGPT OAuth는 공식 PKCE S256, state, nonce와 JWKS를 통한 ID Token 서명 검증을 사용한다. 서버에서 OAuth 트랜잭션을 일회성 소비하고 issuer/client ID/subject별로 계정을 분리한다. 로컬 실행은 공식 동적 등록과 127.0.0.1 콜백을 지원하며 최적화 빌드도 로컬 모드로 실행할 수 있다. 서비스 모드는 승인된 서비스 클라이언트만 사용한다. 사용자가 실제 OpenAI 인증·권한 동의를 완료해야 최종 연결을 확인할 수 있다.

방문자 본인의 구독 사용 권한을 요청하고, 받은 scope를 확인한 뒤 해당 방문자의 암호화된 access token으로 모델을 호출한다. 운영자 API 키로 대체하지 않는다. 토큰 갱신, 연결 해제, 사용량 관리 링크와 한도 오류를 처리한다. 계정별 모델 목록에서 선택하며 Responses는 store:false/stream:true/배열 input을 사용하고 response.completed를 기다린다. 원격 호스팅에 필요한 외부 접근 승인을 코드만으로 취득할 수는 없다.

Node.js 서버 한 대와 영속 디스크로 배포할 수 있다. 여러 계정을 지원하지만 서버리스 임시 디스크나 여러 서버에 SQLite/로컬 녹음을 그대로 분산해서는 안 된다. 그 규모가 필요하면 PostgreSQL과 S3 호환 스토리지, 작업 큐로 이전한다. Docker 배포 예시와 환경 설정은 README를 참고한다.

## 검증의 경계

도메인·저장소 테스트, 로컬 HTTP 통합 테스트, 가상 음성을 이용한 브라우저 흐름 검증을 구분한다. 공식 OAuth 동의 화면으로 이동하는 요청은 확인했지만 사용자 본인의 동의 완료와 실제 구독 모델 평가는 아직 검증하지 않았다. 모델 API 모의 응답 테스트는 실제 평가 정확도를 증명하지 않는다.

`npm run grammar:check -- --yes`는 직접 작성한 학습자형 답변 3개(오류 16곳)로 실제 문법 점검이 찾은 오류 비율과 맞는 문장 오표시를 측정한다. 연결된 계정의 구독 사용량으로 요청 1회를 보내며 `--yes` 없이 실행하면 호출하지 않는다. 실제 사용자 답변은 고정 데이터에 넣지 않는다.

`scripts/check-practice.js`는 한 문항 선택·체험 계정 연결과 같은 출처 복귀·동의 필수·마이크 거부 시 기록 미생성·실제 MediaRecorder 저장·한 번 답변 후 완료·같은 문제 재연습·모바일 배치·실전 설문 유지까지 검증한다. 마이크 입력은 합성이며 실제 OAuth나 유료 AI를 호출하지 않는다.

`scripts/check-listening.js`는 모의 음성 합성 이벤트로 문장·단어 시작 위치·반복·속도 변경·전체 답변 순서·녹음과의 중복 방지·화면 이동 정지·재생 오류·모바일 UI를 검증한다. 이 검사는 실제 스피커 출력이나 음색의 자연스러움을 검증하지 않는다.
