# 배포 전 데이터·비밀정보 점검

2026-11-17 로컬 작업 폴더와 코드 구성을 기준으로 작성했다. 비밀값이나 사용자 답변을 이 문서에 저장하지 않는다. 로컬 자료는 사용자의 데이터이므로 점검 과정에서 삭제하지 않았다.

## 로컬에 기록되는 것

| 위치 | 내용과 주의점 |
| --- | --- |
| `.env.local` | API 키, OAuth secret, AUTH_SECRET 등이 들어갈 수 있는 실행 설정 |
| `.data/opic.sqlite`, `-wal`, `-shm` | 계정·시험·전사·피드백과 암호화한 연결 자격증명. 활성 레코드가 없어도 WAL과 삭제된 페이지에 과거 데이터가 남을 수 있음 |
| `.data/audio/` | 사용자 원본 녹음. 점검 명령은 파일 수만 확인 |
| `.data/session-key` | AUTH_SECRET이 없는 로컬 모드의 암호화 키. DB와 함께 공개하면 안 됨 |
| `.data/chatgpt-host-id` | OAuth 동적 등록에 사용한 설치 식별자 |
| `output/`, `tmp/` | 테스트 DB·화면 캡처·PDF 추출·렌더링 등. 계정과 답변이 담길 수 있음 |
| `.playwright-cli/` | 브라우저 상태·스냅샷·콘솔 로그. 인증 URL 등이 담길 수 있음 |
| `opic_guide.pdf` | 사용자가 제공한 원본 참고 자료. 서비스 실행에 필요하지 않으며 배포 제외 |

이전에 설치했던 로컬 음성 분석용 Python 가상환경·모델·캐시는 제거했다. 현재 GPT 전사에는 해당 모델이 필요하지 않다. 브라우저의 로그인 쿠키는 프로젝트 폴더와 별도로 관리된다.

## 이번에 적용한 제외 규칙

Git과 Docker 모두 환경 설정 파일, 데이터 폴더, 테스트·임시 산출물, 백업, 로그, 로컬 클라우드 자격증명 폴더, 키 파일, SQLite 파일과 Python 캐시를 제외한다. Git은 값 없는 `.env.example`을 예외로 공유하고, Docker는 실행 환경 파일을 이미지에 복사하지 않는다.

기존 Git 목록에 빠져 있던 `tmp/`와 원본 가이드 PDF도 추가했다. `.gitignore`가 과거 커밋·이미 추적 중인 파일·직접 만든 ZIP까지 보호하지는 않는다. Docker 빌드 컨텍스트는 `.dockerignore`로 별도 관리한다.

## 재검사 방법

빌드 후 실행하면 최신 브라우저 번들도 확인할 수 있다.

```bash
npm run build
npm run security:check
```

점검 스크립트는 다음을 수행한다.

1. 배포 후보 소스에서 대표적인 OpenAI 키·개인 키·AWS 키·GitHub 토큰·JWT 패턴을 찾는다.
2. `.env.local`에 현재 설정한 긴 비밀값이 소스나 `.next/static` 브라우저 번들에 그대로 포함됐는지 검사한다. 값은 출력하지 않는다.
3. 격리된 임시 Git 저장소에서 현재 `.gitignore`의 민감 경로 예시를 검사한다. 프로젝트에 저장소를 만들거나 커밋하지 않는다.
4. 현재 폴더가 Git 저장소이면 추적 중인 민감 경로를 확인한다. 저장소가 아니면 추적 파일과 이력을 미검사로 표시한다.
5. 기본 `.data/`의 테이블별 행 수·녹음 파일 수·민감 파일 존재 여부를 읽는다. 계정·토큰·전사·녹음 내용은 출력하지 않고 데이터를 삭제하지 않는다.

일치 후보가 있으면 종료 코드 1로 알린다. 실제 비밀값인지 사람이 확인해야 한다. 패턴에 없는 비밀값, 인코딩·분할된 값, 과거에 썼던 키, 외부 저장소와 과거 커밋은 이 검사만으로 찾지 못할 수 있다. 사용자 지정 `DATA_DIR`은 기본 폴더 검사와 별도로 점검한다. Docker 이미지를 실제 빌드·실행해 검사하는 명령은 아니다.

## Git과 파일 공유

점검 시작 시 현재 폴더에는 Git 저장소가 없었다. 기존 커밋·원격 저장소에서 이미 공개된 정보가 없다고 단정할 수 없다. 초기 커밋 전에는 제외 규칙과 `git status --short --untracked-files=all`을 확인한다.

이미 커밋한 민감 파일을 발견하면 추적 해제만으로 과거 노출이 해결되지 않는다. 노출된 키·토큰은 폐기하고 재발급하며 기존 이력과 배포 산출물도 점검한다. 소스 ZIP은 전체 작업 폴더를 그대로 압축하지 않는다.

## 운영으로 복사하지 말아야 할 것

- 로컬 `.env.local`, `.data/`, 암호화 키와 OAuth 연결 레코드.
- 개인 녹음·전사·피드백과 테스트 계정 DB.
- 브라우저 프로필·쿠키·Playwright 상태와 인증 URL이 들어간 로그.
- 원본 가이드 PDF와 권한을 확인하지 않은 공식 시험 자료.

운영에는 별도 비밀값, 비어 있는 영속 저장소, 승인된 서비스 OAuth 설정과 HTTPS를 사용한다. 로컬 자격증명 복사로 서비스 승인을 대체하지 않는다. 보관 기간과 백업·삭제 정책은 운영자가 별도로 정해야 한다.

## 코드에서 확인한 방어와 점검 범위

API는 세션 소유권·시험 상태를 검사하고 변경 요청은 Origin을 검사한다. 로컬 실행에서는 127.0.0.1·localhost의 3000번과, 3000번이 사용 중일 때 개발 서버가 쓰는 3001번만 허용한다. 서비스 모드는 `APP_URL`만 허용한다. OAuth 토큰은 서버에서 암호화해 저장하고 클라이언트에 반환하지 않는다. 녹음 파일명은 서버에서 생성하며 원본 파일 경로를 공개하지 않는다. 서비스 모드에는 HTTPS 설정과 충분한 AUTH_SECRET이 필요하고 로컬 체험 계정을 제공하지 않는다.

이 문서는 비밀정보·데이터 포장 점검이다. 침투 테스트, 전체 의존성 취약점 감사, 실제 OAuth 권한·운영 인프라 보안 검증을 수행했다는 의미는 아니다.
